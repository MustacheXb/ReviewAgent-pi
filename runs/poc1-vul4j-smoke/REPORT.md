- **实验 ID**: `poc1-vul4j-smoke`

- **规模**: Vul4J 3 case（VUL4J-38 / 52 / 79）× 配置 A/B/C/D/E × 3 reps = **45 单元，全部完成**
- **模型**: `deepseek-v4-flash`（ADR-0002 锁定档：thinking enabled + reasoning_effort high）

## 0. 配置速览（五配置含义）

| 配置 | 含义 |
|---|---|
| **A** | 裸 diff、无工具——只喂 MR diff，不读仓库、不给工具；质量下限参照 |
| **B** | 确定性 prefetch 预取、无工具——harness 按固定规则预取相关上下文注入，模型不自主取数；**论文主推配置** |
| **C** | fullRepo 全量上下文 + 工具——整个仓库进上下文并开放工具调用；S/A/B 判定的 anchor 基准 |
| **D** | 工具 + stablePrefix——仅注入稳定前缀，上下文由模型经工具调用自主拉取 |
| **E** | D + Context Ledger——在 D 之上加已取上下文账本，避免重复拉取 |

> 五配置共享同一检视 prompt 与输出契约，差异仅在「上下文如何进入模型」：不进（A）/ harness 预取（B）/ 全量注入（C）/ 模型自取（D）/ 模型自取 + 去重（E）。

## 1. 一句话结论

**B 配置（确定性 prefetch 管线）以 C 配置（全量上下文 anchor）16.9% 的 token 成本（rep2+ 热口径）取得全场最高的 lineRecall（36.1%）与 93.5% 的 cache 命中率**——成本侧结论强（远优于论文 ≤30% 目标），质量侧为相对领先但绝对值低，且 anchor 自身 recall 退化（rep2+ 为 0%）使 S 判定的质量门槛失效，**当前 "B=S" 只在成本与缓存两维成立**。

## 3. S/A/B 判定（ADR-0004 规则口径，anchor = C）

| 配置 | Outcome | lineRecall | totalTokens | cacheHit | 判定依据（rep2+ 热口径） |
|---|---|---|---|---|---|
| A（裸 diff 无工具） | **A** | 13.9% | 29,279 | 84.8% | Token 7.5%/C ✓；CacheHit 84.8% ≥80% ✓ |
| B（prefetch 预取，论文主推） | **S** | 36.1% | 66,104 | 93.5% | Token 16.9%/C ✓（门槛 30%）；CacheHit 93.5% ≥85% ✓ |
| C（全量上下文+工具，anchor） | BELOW_B | 0% | 391,700 | 95.7% | anchor 自身：Token 100%/C >50% |
| D（工具+stablePrefix 自主拉取） | **A** | 13.9% | 116,840 | 84.1% | Token 29.8%/C ✓（压线）；CacheHit 84.1% ≥80% ✓ |
| E（D+Context Ledger） | **B** | 8.3% | 137,098 | 84.7% | Token 35.0%/C 超 A 级 30% 门槛，落 B 级（≤50%） |

### ⚠️ anchor 退化警示（本报告最重要的限定条件）

**anchor C 的 rep2+ lineRecall = 0%**（rep1 冷 16.7%，rep2/3 热未命中任何 ground truth 行）。按 ADR-0004，Recall 门槛 = C×90%/80%/70% = 0，**全部配置的质量门槛为真空通过**：

- B 的 "S" 中，**Token（16.9% ≤30%）与 CacheHit（93.5% ≥85%）是真实达标**；Recall ≥ C×90% 与 Precision ≥ C×100% 是除以 0 锚点的退化判定
- 质量侧的可信表述是**相对排序**：B 36.1% > A 13.9% = D 13.9% > E 8.3% > C 0%（rep2+）；B 的 linePrecision 58.3% 亦为全场最高
- 成因初判：C 的 9 单元中 6 个产出 0 findings（VUL4J-79 rep1/2、VUL4J-52 rep2/3 等全量上下文下模型未报或被验证阶段全部否决）；3 case 样本下噪声极大，**该警示必须随正文进入论文，或在扩样后重判**

## 4. 核心指标（rep2+ 热口径为主口径，mean ± std）

**指标定义**（规则粗筛口径，判定链第一级）：**lineRecall** = TP/(TP+FN)，真值漏洞行位中被检视报告正确命中的比例（「该找的找到了多少」，低 = 漏报多）；**linePrecision** = TP/(TP+FP)，报告指出的问题中命中真值的比例（「报出来的有多少是对的」，低 = 误报多）。TP 口径：Finding 与真值位置同文件 ∧ 行位落在真值区间（容差 0）∧ 漏洞性质等价；真值 = Vul4J 修复补丁触碰的漏洞行位（含 CWE 性质标注）。

| 指标 | A（裸 diff） | B（prefetch 预取） | C（全量+工具，anchor） | D（自主工具拉取） | E（D+Ledger） |
|---|---|---|---|---|---|
| lineRecall | 13.9% ±12.7% | **36.1%** ±12.7% | 0% ±0% | 13.9% ±12.7% | 8.3% ±14.4% |
| linePrecision | 25% ±25% | **58.3%** ±38.2% | 0% ±0% | 50% ±23.6% | 12.5% ±17.7% |
| lineF1 | 17.8% ±16.8% | **41.7%** ±14.4% | 0% ±0% | 45.2% ±16.8% | 12.5% ±17.7% |
| totalTokens | 29,279 ±648 | **66,104** ±6,234 | 391,700 ±167,855 | 116,840 ±36,270 | 137,098 ±37,300 |
| totalInputTokens | 10,980 ±1,422 | 32,973 ±6,136 | 356,935 ±165,826 | 83,216 ±28,439 | 101,199 ±38,669 |
| cacheHitRate | 84.8% ±1.5% | **93.5%** ±1.2% | 95.7% ±1.9% | 84.1% ±4.2% | 84.7% ±5.9% |
| toolCalls | 0 | 0 | 6 ±0 | 6 ±0 | 6 ±0 |
| rounds | 1 | 1 | 2 ±1 | 1 | 2 ±0 |
| CARC（输出 token） | 19,956 | 35,235 | 47,231 | 45,630 | 48,735 |

**解读**：

- **B/C 成本比**：热口径 **16.9%**（66,104/391,700）、冷口径 19.1%、9 单元全程总账 17.5%——三个口径一致地远低于论文 30% 目标。且这是在 C 自身 cacheHit 95.7%（全量上下文稳定前缀充分生效）的**不利基准**下取得，成本优势不是靠牺牲 anchor 缓存效率换来的
- C 的贵有两层：输入侧全量上下文（357k input vs B 33k，10.8 倍）+ 输出侧多轮（CARC 47k vs 35k + rounds 2 vs 1）
- C/D/E 的 toolCalls 全部打满 6 次预算上限（±0）——`MAX_TOOL_CALLS=6` 是紧约束，模型工具需求未饱和（对 D/E 的相对评价有轻微系统性压制）
- A（无工具、裸 diff）与 B（prefetch、无工具）单轮完成；B 以 2.26 倍于 A 的 token 换取 2.6 倍 recall 与 +33pt precision——prefetch 管线的边际收益为正

**rep1 冷口径补充**（首跑无缓存）：B recall 16.7% / C 16.7%（anchor 冷跑命中）、B cacheHit 80.2% / C 94.9%；B/C 冷成本比 19.1%。冷热口径结论方向一致。

## 5. 预热曲线（cacheHitRate，per-rep 跨 case 均值）

| Rep | A（裸 diff） | B（prefetch 预取） | C（全量+工具） | D（自主工具拉取） | E（D+Ledger） |
|---|---|---|---|---|---|
| rep1（冷） | 76.1% | 80.2% | 94.9% | 79.7% | 89.3% |
| rep2 | **85.2%** | **93.9%** | 96.1% | 85.3% | 81.0% |
| rep3 | 84.4% | 93.0% | 95.2% | 82.9% | 88.4% |

- B 预热幅度最大（80.2% → 93.9%，+13.7pt）：prefetch 注入的长前缀首跑未命中、rep2 起整体进缓存——**分层缓存设计按预期工作**
- A 的 76.1% → 85.2%（+9.1pt）：即使无 prefetch，稳定 Zone A 前缀（system prompt + diff）也能预热
- C 起点即 94.9%：全量上下文本身即超长稳定前缀，缓存利用率高——再次强调 B 的成本优势不是缓存运气的产物
- E 的 rep2 回落（89.3% → 81.0%，±12.3pt 高方差）：Ledger 惰性态/功能态切换下的前缀扰动，样本量下不做过度解读

**口径**：totalTokens = 未命中输入（`prompt_cache_miss_tokens`）+ 命中输入（`prompt_cache_hit_tokens`）+ 输出（`completion_tokens`，含思考 token）。

- **结构**：命中输入 71.4% / 输出 22.6% / 未命中输入 6.0%——缓存把输入侧费用压到未命中价的约 1/10 量级（按 DeepSeek 命中/未命中差价折算）

## 7. 附属观测

- **Cache Break 分类（US13）**：五配置 45 run 的相邻请求前缀分歧 **全部为 0**（MODEL/SYSTEM_PROMPT/TOOL_SCHEMA/CONTEXT_REORDERED 均 0）——Zone A 稳定前缀字节纪律在线上得到验证
- **Context Ledger 去重**：C 134 次 / D 119 次 / E 138 次工具调用，去重 1 次（E，0.7%）——3 case 内重复调用极少，Ledger 的价值需在更长会话/更大样本上验证
- **人工复核抽样**：seed `poc1-human-review-2026`、10% 抽率，45 单元抽中 5 份表单（`human-review/` 目录）
- **Judge 阶段**：未执行。同 id 重跑加 `--judge` 即可增量补（45 单元全部 resumed，仅 judge 调用计费）

## 8. 结论与建议

**论文叙事支撑点（已验证）**：

1. **成本核心指标成立**：B/C = 16.9%（热）/ 19.1%（冷），远优于 "20~30% 成本" 目标区间下限
2. **Cache Hit ≥85% 成立**：B 热 93.5%（rep2 起 ≥93%），且预热曲线展示清晰的分层缓存生效路径
3. **零 Cache Break**：字节稳定纪律的工程主张获得线上验证

**风险与限定（须随论文披露）**：

1. **anchor 质量退化**：C 的 rep2+ recall 0% 使质量门槛真空——B 的质量优势只能以相对排序表述；建议扩样（≥10 case）后重判，并在判定规则中处理 anchor recall 为 0 的退化情形（如锚点最低 recall 门槛或绝对+相对双门槛）
2. **3 case 样本量**：所有 ±std 都大（B recall ±12.7pt），只支持方向性结论
3. **MAX_TOOL_CALLS=6 紧约束**：C/D/E 工具调用全部打满预算，压制了 agent 配置的上限对照
4. **judge 缺位**：规则口径 verdicts 未经 LLM 裁定复核

**下一步建议**（按优先级）：

1. 补 judge 阶段（需 GPT judge key，增量费用仅 judge 调用）
2. 人工复核 5 份抽样表单，校准规则口径
3. 扩样至 10~15 case 复跑（预算 ~2,500 万 token 量级，含 anchor 重判）
4. 评估放宽 MAX_TOOL_CALLS（如 12）做一次 D/E 对照，排除预算压制混淆
