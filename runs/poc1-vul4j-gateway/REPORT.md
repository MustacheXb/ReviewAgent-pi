## 0. 配置速览（五配置含义）

| 配置 | 含义 |
|---|---|
| **A** | 裸 diff、无工具——只喂 MR diff，不读仓库、不给工具；质量下限参照 |
| **B** | 确定性 prefetch 预取、无工具——harness 按固定规则预取相关上下文注入，模型不自主取数；**论文主推配置** |
| **C** | fullRepo 全量上下文 + 工具——整个仓库进上下文并开放工具调用；S/A/B 判定的 anchor 基准 |
| **D** | 工具 + stablePrefix——仅注入稳定前缀，上下文由模型经工具调用自主拉取 |
| **E** | D + Context Ledger——在 D 之上加已取上下文账本，避免重复拉取 |

> 五配置共享同一检视 prompt 与输出契约，差异仅在「上下文如何进入模型」：不进（A）/ harness 预取（B）/ 全量注入（C）/ 模型自取（D）/ 模型自取 + 去重（E）。

## 1. 一句话结论

**同一模型名（deepseek-v4-flash）换 provider 部署后，实验结论的量级与方向都发生了实质变化**：B 配置在网关口径下以 C 配置 10.3% 的 token 成本（rep2+ 热口径）取得 23.6% 的 lineRecall（全场最高）与 75% 的 linePrecision（全场最高），质量门槛首次非真空达标（anchor C 复活，rep2+ recall 12.5%）；但 B 的 cacheHit 83.5% 距 S 级 85% 门槛差 1.5pt 落 A 级——**provider 侧缓存基础设施（异步预热 45~90s）直接改写了缓存经济性**。Token 消耗总账 11,287,939（官方同规模 6,512,767，1.73 倍），且差异方向因配置而异：单轮配置 A/B 更省（输出收敛）、多轮工具配置 C/D/E 更贵（1.7~2.7 倍，工具循环激进化）。

## 3. S/A/B 判定（ADR-0004 规则口径，anchor = C，rep2+ 热口径）

| 配置                      | Outcome | lineRecall | totalTokens | cacheHit | 判定依据                                                                                                  |
| ----------------------- | ------- | ---------- | ----------- | -------- | ----------------------------------------------------------------------------------------------------- |
| A（裸 diff 无工具）           | BELOW_B | 5.6%       | 19,698      | 40.4%    | Recall 5.6% < C×70% = 8.75% ✗                                                                         |
| B（prefetch 预取，论文主推）     | **A**   | **23.6%**  | **43,458**  | 83.5%    | Recall ≥ C×80% ✓；Precision 75% ≥ C×100% ✓；Token 10.3%/C ✓；CacheHit 83.5% < 85%（S 级差 1.5pt，A 级 ≥80% ✓） |
| C（全量上下文+工具，anchor）      | BELOW_B | 12.5%      | 424,005     | 94.0%    | anchor 自身：Token 100%/C >50%                                                                           |
| D（工具+stablePrefix 自主拉取） | BELOW_B | 0%         | 384,908     | 86.8%    | Recall 0% ✗；Token 90.8%/C >50% ✗                                                                      |
| E（D+Context Ledger）     | **B**   | 11.1%      | 200,425     | 84.4%    | Recall ≥ C×70% ✓；Token 47.3%/C ≤50% ✓                                                                 |

### anchor 复活（与官方口径的关键差异）

官方口径下 C 的 rep2+ recall 为 0%（anchor 退化，质量门槛真空）；**网关口径下 C 的 rep2+ recall = 12.5%**——anchor 有效，质量门槛首次非真空：

- B 的质量优势是**真实判定**：Recall 23.6% ≈ C×189%（门槛 80%）、Precision 75% = C×400%（门槛 100%）
- B 落 A 级的唯一失分项是 CacheHit 83.5%（差 1.5pt），且该指标受网关异步预热系统性压制（见 §5）
- D 在网关口径下崩塌（recall 0%、token 90.8%/C）：部署行为激进工具循环 + 自主拉上下文策略的组合在网关上不可控

## 4. 核心指标（rep2+ 热口径，mean ± std）

**指标定义**（规则粗筛口径，判定链第一级；judge 未执行，见 §8）：

- **lineRecall = TP / (TP + FN)**——真值漏洞行位中被检视报告正确命中的比例，回答「该找的找到了多少」（低 = 漏报多）
- **linePrecision = TP / (TP + FP)**——检视报告指出的问题中命中真值的比例，回答「报出来的有多少是对的」（低 = 误报多）
- TP 口径：检视 Finding 与真值位置**同文件 ∧ 行位落在真值区间（容差 0）∧ 漏洞性质等价**；一个真值位置仅计一次命中，重复检出记 DUPLICATE 误报；真值 = Vul4J 修复补丁触碰的漏洞行位（含 CWE 性质标注）

| 指标               | A（裸 diff）     | B（prefetch 预取）    | C（全量+工具，anchor）  | D（自主工具拉取）       | E（D+Ledger）     |
| ---------------- | ------------- | ----------------- | ---------------- | --------------- | --------------- |
| lineRecall       | 5.6% ±9.6%    | **23.6%** ±10.5%  | 12.5% ±21.7%     | 0% ±0%          | 11.1% ±19.2%    |
| linePrecision    | 25% ±35.4%    | **75%** ±25%      | 18.8% ±26.5%     | 0% ±0%          | 25% ±35.4%      |
| lineF1           | 12.5% ±17.7%  | **43.9%** ±23.4%  | 18.8% ±26.5%     | 0% ±0%          | 20% ±28.3%      |
| totalTokens      | 19,698 ±4,160 | **43,458** ±9,478 | 424,005 ±241,849 | 384,908 ±66,205 | 200,425 ±23,900 |
| totalInputTokens | 10,654 ±1,563 | 31,833 ±6,227     | 375,910 ±228,598 | 321,975 ±62,748 | 162,626 ±24,205 |
| cacheHitRate     | 40.4% ±17.7%  | 83.5% ±1.4%       | **94.0%** ±0.8%  | 86.8% ±1.5%     | 84.4% ±2.1%     |
| toolCalls        | 0             | 0                 | 6 ±0             | 6 ±0            | 6 ±0            |
| rounds           | 1             | 1                 | 2 ±1             | 4 ±1            | 3 ±1            |
| CARC（输出 token）   | 15,346        | 16,920            | 71,280           | 101,388         | 62,270          |

**解读**：

- **B/C 成本比**：热口径 **10.3%**（43,458/424,005）、冷口径 4.5%、9 单元全程总账 7.0%——三个口径一致地远低于论文 30% 目标，且优于官方口径的 16.9%
- **B 的输出收敛**：CARC 16,920（官方 35,235，−52%）——网关部署的单轮行为输出更短，直接压低了 A/B 的成本
- **C/D/E 的输出膨胀**：CARC 71k / 101k / 62k（官方 47k / 46k / 49k）——多轮工具循环在网关部署上 rounds 拉满（D 4 轮、E 3 轮），每轮重复注入上下文推高输入与输出
- **A 的 cacheHit 崩塌**（40.4% vs 官方 84.8%）：A 单轮秒级完成，rep2 距 rep1 不足网关异步预热窗口（45~90s）→ 系统性 miss。这是 provider 缓存实现差异的直接观测（见 §5）
- **D/E 对照（网关口径）**：E 与 D 单元成本几乎相同（289,161 vs 289,314）但 recall 11.1% vs 0%——Ledger 在激进工具循环下起到止损作用（去重 0% 但轮次 3 vs 4）

**rep1 冷口径补充**：C 冷跑 930,162 token/单元（官方 319,226，2.9 倍）；B 冷 41,762（官方 61,063，−32%）；B/C 冷成本比 4.5%。

## 5. Provider 对照（论文核心证据章节）

> 论文叙事：**Token 消耗与优化效果不仅由 harness 策略决定，也由模型 provider 的部署行为与缓存基础设施决定**——两者是乘法关系。同一模型名在两个 provider 部署上的同规模对照（各 45 单元，同 case、同配置、同锁定档位）提供了受控证据。

### 5.1 行为参数对照（rep2+ 热口径）

| 维度 | 官方 deepseek-v4-flash | 网关 deepseek-v4-flash-ga-260731 |
|---|---|---|
| 部署版本 | 官方 API | ga-260731（火山引擎） |
| D 配置 rounds | 1 | **4（打满 MAX_ROUNDS=5 附近）** |
| E 配置 rounds | 2 | 3 |
| B 配置 CARC（输出） | 35,235 | 16,920（−52%） |
| D 配置 CARC（输出） | 45,630 | **101,388（+122%）** |
| D 配置 totalTokens | 116,840 | **384,908（3.3 倍）** |

同名模型、同 prompt、同工具集，**部署行为差异导致单配置 token 消耗差 3.3 倍**。且方向不一致：单轮配置输出收敛（更省）、多轮工具配置循环激进化（更贵）——provider 差异不是可简单折算的均匀乘数，而是与 harness 策略（有无工具、自主拉上下文）交互作用。

### 5.2 缓存基础设施对照

| 维度 | 官方端点 | 火山网关 |
|---|---|---|
| 缓存建立 | 即时（相邻请求命中） | **异步预热 45~90s**（精确探测：t=60s 仍 miss，t=90s 命中） |
| 命中粒度 | 全前缀 | 块对齐部分前缀（实测 768/938） |
| usage 字段 | `prompt_cache_hit/miss_tokens` | `prompt_tokens_details.cached_tokens`（需适配，`27b9400`） |
| A 配置 cacheHit | 84.8% | **40.4%（−44pt）** |
| B 配置 cacheHit | 93.5% | 83.5%（−10pt） |
| C 配置 cacheHit | 95.7% | 94.0%（持平） |

**缓存的可用性本身是 provider 属性**：轻前缀快速循环的配置（A：单轮秒级）在异步预热网关上命中率崩塌；长稳定前缀配置（C：全量上下文一次建立反复命中）不受影响。这意味着 **harness 层的缓存优化（Zone A 稳定前缀纪律）效果上限由 provider 缓存实现封顶**——我们的优化主张必须与 provider 维度联合陈述。

### 5.3 总账对照（45 单元）

| 配置 | 官方合计 | 网关合计 | 倍率 | 方向 |
|---|---|---|---|---|
| A（裸 diff 无工具） | 270,345 | 195,121 | 0.72× | 更省（输出收敛） |
| B（prefetch 预取） | 579,813 | 386,035 | 0.67× | 更省（输出收敛） |
| C（全量上下文+工具，anchor） | 3,307,877 | 5,500,500 | 1.66× | 更贵（多轮重复注入） |
| D（工具+stablePrefix 自主拉取） | 958,331 | 2,603,830 | **2.72×** | 更贵（工具循环激进化） |
| E（D+Context Ledger） | 1,396,401 | 2,602,453 | 1.86× | 更贵（同上，Ledger 止损） |
| **合计** | **6,512,767** | **11,287,939** | **1.73×** | — |

**结论**：论文中 "20~30% 成本获得 80~90% 质量" 的主张应在 provider 维度上标注适用条件——B/C 成本比在两个 provider 上分别为 16.9% 与 10.3%（均达标），但绝对成本、缓存命中率、配置间排序（D 在网关上崩塌）都随 provider 变化。**Token 优化 = harness 策略优化 × provider 基础设施优化**，缺一不可。

## 8. 附属观测

- **Cache Break 分类（US13）**：五配置 45 run 相邻请求前缀分歧**全部为 0**——Zone A 字节稳定纪律在网关上同样成立（与官方口径一致，provider 无关的 harness 属性）
- **Context Ledger 去重**：C 182 / D 223 / E 257 次工具调用，去重 0%——重复调用在激进循环下仍少，Ledger 价值需更大样本验证
- **人工复核抽样**：seed `poc1-human-review-2026`、10% 抽率，45 单元抽中 5 份表单（`human-review/` 目录）
- **Judge 阶段**：未执行。同 id 重跑加 `--judge` 即可增量补（需 OPENAI_API_KEY）
- **网关 usage 抖动**：同内容请求的 `prompt_tokens` 计数有 ±8% 波动（官方稳定）——指标噪声轻微增加，已在报告口径中接受

## 9. 结论与建议

**论文叙事支撑点（网关口径新增）**：

1. **Provider 维度证据成立**：同一模型名两个部署，总账 1.73 倍、单配置最高 3.3 倍、方向因配置而异——token 消耗与优化效果强依赖 provider 部署行为与缓存基础设施（§5 三组对照）
2. **B 的质量优势首次非真空**：anchor C 复活（rep2+ recall 12.5%），B 的 Recall/Precision 双第一是真实判定
3. **B/C 成本比 10.3%**（热），优于官方口径的 16.9%，远低于 30% 目标
4. **零 Cache Break 跨 provider 复现**：字节稳定纪律是 harness 属性，不受端点影响

**风险与限定**：

1. **B 的 S 级判定被 provider 缓存压制**：cacheHit 83.5% 差 1.5pt（rep3 已过线 85.3%）；论文应标注该指标的 provider 条件性，或以官方端点数据支撑 S 级主张
2. **3 case 样本量**：所有 ±std 大（B recall ±10.5pt），只支持方向性结论；30 case 目标集已物化入库（`f4244d3`），扩样即取即用
3. **D 配置在网关上崩塌**（recall 0%）：部署行为 × 自主工具策略的交互风险，论文中作为 provider 敏感性的例证而非配置否定
4. **judge 缺位**：两套 45 单元均为规则口径 verdicts

**下一步建议**（按优先级）：

1. 补 judge 阶段（两套实验同批补，需 GPT judge key）
2. 30 case 扩样（数据就绪；建议网关与官方各跑一轮以固化 provider 对照，或只跑网关 + 引用官方 smoke 作参照）
3. Phase 1 DSH 迁移启动（前置条件已满足：实验结论 B 胜出、报告定稿、工程基线待 PR #15 合入）
