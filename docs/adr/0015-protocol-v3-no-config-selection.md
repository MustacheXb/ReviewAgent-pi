# 0015. 协议 v3——配置选择根除的契约代数切换

**状态**：已接受（2026-11-03，#32 范围 1 落地；方向决策与判定项见 ADR-0014 §10，本 ADR 记录完整契约决策）
**决策基线**：`production/e-only`（分支收口后为 `main`）；Demo 线不持有 0015（同号不同文纪律，ADR-0014 §8）
**关联**：ADR-0011（生产入口切流 config E）、ADR-0012（stdio JSONL 长驻与错误码段位）、ADR-0013（统一契约与拓扑 B——v2 参数面）、ADR-0014（分支策略与 §10 v3 判定项）、追踪 issue #32 / spec #33
**适用范围**：本仓主线（`MustacheXb/ReviewAgent-pi` 生产分支）

## Context

- ADR-0011 切流后 E 是唯一生产内核形态，但协议 v2 仍要求 `review.submit` 显式传 `configId`（A–E 选择面）：「无配置选择时代」的契约寄生着「配置选择时代」的参数形——客户端装配多一个必填参数，「选错配置」的输入空间在生产线上依然存在。
- ADR-0014 拍板分支分叉（main 生产 / demo 研究复现）并选定 **v3 破坏性变更**路线（明确否掉「v2 收窄合法域」的兼容路线）。本 ADR 落地完整决策：参数模型、错误码、版本断言语义、内化口径与历史兼容。

## Decision

### 1. 代数切换信号唯一化

`capabilities.protocolVersion` = **3** 是新代数唯一切换信号（先例：v2 即唯一切换信号，ADR-0013 决策 3）。单一常量单源（`rpc/protocol.ts` 的 `PROTOCOL_VERSION`），服务端报告与客户端断言共用。

### 2. submit 参数模型删除 configId

- `review.submit` 参数：`caseId` / `repoPath`（CLI / stdio 可省走 cwd 缺省链，HTTP 必填显式）/ `diff` 判别联合——**无 `configId` 字段**（必填与可选都不再有）。
- 携带 `configId` 的请求 → **`-32019 CONFIG_ID_REJECTED` 专用错误码显式拒绝**：
  - 不静默忽略（零静默纪律）；不复用泛化 `-32602 invalid_params`（可编程分类——客户端与脚本程序化识别「配置选择已根除」这一契约变化）；
  - **契约代数错误先于字段校验发射**：携带即拒、与值无关——连 `"E"` 也拒，不存在「合法携带」；
  - 错误码自 `-32019` 起分配并登记进错误码表单源（此前至 `-32018`，ADR-0012 段位纪律延续），防号码复用。
- CLI / stdio / HTTP 三形态共用同一校验器（`validateReviewRequest` 单源，无 configId 形）——同一拒绝语义跨形态一致。

### 3. configId 内化为服务端派生常量

- `configId` 从请求面参数内化为派生常量 `"E"`（`contracts/config.ts` 的 `CONFIG_E` 单源）：RunRecord / 审计 / disposition / 幂等对比口径恒输出 `"E"`；`runReview` 不接受 configId 输入（内核单源派生，派生点唯一）。
- CLI `--config` 旗标彻底移除：无旗标即 E；传入（任意值含 E）→ 用法错误并列出合法旗标——旧脚本立刻暴露而非悄悄换义。
- 类型面双轨：写面 `ConfigId` 塌缩为单值 `"E"`（编译期不存在「选错配置」的输入空间）；读面 `HistoricalConfigId`（A–E 历史值域）保留给历史 RunRecord / 处置回溯。回溯锚字段名不变。

### 4. 客户端版本硬断言（双向明确）

typed 客户端（HTTP client + stdio 宿主客户端）在 `capabilities()` 出口对 `protocolVersion` 硬断言：≠ 3 即抛人话错误（直接说明「v3 起无配置选择」与对端代数——排障不需要翻本 ADR）。双向覆盖：

- v3 client → v2 server：断言抛错（不静默降级成诡异行为）；
- v2 client → v3 server：v2 submit 必带 `configId` → `-32019` 拒绝兜底。

### 5. 历史 A–D RunRecord 只读兼容

历史 A–D RunRecord 照常读取与处置：disposition 回溯锚、人工接受率 KPI 对历史 A–D 处置数据照常计算（值域收窄不破读面）。新产物恒 `configId:"E"`，统计面口径单义。

### 6. 跨分支版本分叉为预期态

主线 v3 / Demo 线 v2，**不互通、不做兼容层**（ADR-0014 §10）：两线的 server / client 各自闭环；版本错配的第一入口是断言错误信息（自带代数说明与对端代数）。

## Options（为什么不是别的）

- **v2 收窄合法域（configId ∈ {E}，A–D 显式报错）**：零客户端改动的兼容路线，已否（ADR-0014 §10）——契约代数单义优先：「无配置选择时代」不寄生于「配置选择时代」的参数形。与 stdio v1 旧扁平 `diff` 形不保 alias（ADR-0013）同构。
- **静默忽略携带的 configId**：违背零静默纪律——客户端以为选中了配置、服务端实际恒 E，错配无痕滑过。
- **复用 `-32602 invalid_params`**：不可编程分类——迁移期旧客户端无法区分「字段拼错」与「契约代数已变」，错误处理路径无法分叉。
- **保留 `--config E` 合法档（仅拒 A–D）**：协议面拒携带、CLI 面收合法值的双口径撕裂「无配置选择」语义；旗标根除单义。
- **v3↔v2 适配层 / 兼容层**：跨分支不互通是预期态（§6），适配层只为不存在的互通需求付费。

## Consequences

- **正**：契约代数单义（submit 形状即语义）；「选错配置」输入空间在编译期（`ConfigId` 单值类型）与协议期（携带即拒）双面根除；版本错配双向人话报错；`-32019` 可编程分类。
- **负/风险**：v2 客户端连主线 server 即断（主线 / Demo 线不互通——预期态）；携带 configId 的既有脚本须改造（迁移指引 = 错误信息本身）；`-32019` 起段位须防复用（错误码表单源已登记）。
- **中性**：RunRecord 的 `configId` 字段保留（新记录恒 `"E"`、历史记录 A–E 只读）——字段是回溯锚，不再是选择面。
