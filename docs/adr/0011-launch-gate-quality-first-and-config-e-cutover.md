# 0011. 上线门口径——质量门主判 + 对齐门转形态记录 + 切流 config E

**状态**：已接受（2026-10-20，用户决策「按推荐路径来」）
**关联**：ADR-0007（对齐门协议 v2）、ADR-0009（pi 内核从 0 重写与 P4b 退役时点表）、P5b 对照报告（eb81397，`docs/report/Phase 2 pi 内核全量对照报告.md` §5/§12/§13）、生产化四必做（#12–#15，2026-10-19 关闭）

## Context

- 上线门原定义（总体架构设计方案 §787）：**四必做全绿 + P5 对照报告通过双门**。
- 现状：四必做全绿已达成；P5b 对齐门判 **FAIL（如实）**——16 IN / 4 OUT（OUT 全是 cacheHitRate），lineRecall / cacheHitRate 配对检验 FAIL。
- FAIL 的实证语义（P5b §5.3/§13）：**形态分歧记录，非劣化**——方向读数 pi 全线更高（judge recall C/D/E +24~31pp）、token 更低（−44~51%）；门本身方向盲（报告 U2）；cacheHitRate 的 FAIL 混合 221h 网关时段漂移、与序列化方言不可分解（U1）。
- 同窗口复跑不可行：P4b 单内核收口（4a7c221）已物理退役 `src/` 评测装置侧运行时——POC1 基线侧（main/noise）无运行时，让时段效应退场的双侧复跑无法执行。
- 判级面：pi 侧锚活（C 热口径 recall 0.2468，五配置最高）条件下 **E 判 B**；DSH 三侧 B=S 是锚塌缩产物（锚 recall 0.0097–0.0761，判级退化为 token+缓存门），跨侧判级不可直接互比。
- 质量证据（四侧同协议，450 单元）：E judge recall **0.5962** 冠五配置、totalTokens **125.2k** 最低档、零 finding 率 **5.3%**（dsh 35.3%）、billed 总账 **21.32M** 四侧最低。

## Decision

1. **上线判据改为质量门主判**：四必做全绿（✅）+ 锚活判级 ≥ B（E 实测 = B）+ 生产入口选型证据（E 选型 + 上表四侧对照）。**上线门判定：通过（2026-10-20）。**
2. **对齐门转形态记录职责**：不再作上线判据。后续内核变更仍跑门（漂移检测照旧），结论只进对照报告；其 FAIL 语义（形态分歧）与方向盲限制（U2）随本 ADR 一并落档。
3. **cacheHitRate 跨侧对比永久带时段限定**：跑评测/门前网关前缀门探针留痕（#18 机制固化为跑前必做）；时段效应登记为环境类别，不作内核归因。
4. **切流 config E**：`review-pi review` 缺省 config B → E；程序化接口（`ReviewRunInput.configId`）改必填显式——「缺省」单义只存在于 CLI 用户面，双层缺省消除（编译期锁：缺 configId 即红）。

## Options（为什么不是别的）

- **同窗口复跑收口 cacheHitRate**：不可行——基线侧运行时已随 P4b 退役；重建 POC1 harness 违背单内核收口方向，且只为消除一个已可登记归因的环境混杂，成本不成比例。
- **判据修订（方向敏感门 / cacheHitRate 出判据）**：可行但属 ADR-0007 协议演进——留给下一次需要跑门的内核变更按需立项；本决策直接解除对齐门对上线的约束，不必先改协议。
- **维持原上线门口径（对齐门 FAIL 即卡上线）**：与 FAIL 的实证语义矛盾（方向有利的分歧），且卡点在现有手段下不可消除（复跑不可行）——照字面执行等于永久卡死。

## Consequences

- **正**：上线路径打通且判据可解释（质量门证据链完整、可复算）；CLI 缺省与生产入口选型单义对齐；程序化调用点全显式化（原 `?? "B"` 的隐式依赖由编译器暴露后逐个落定）。
- **负/风险**：对齐门不再拦上线——内核漂移的上线前拦截弱化一层（缓解：门照跑 + 对照报告留痕 + 模型迁移门兜底换模型风险）。E 判级 = B 非 S，且 B 档 recall 判据余量极窄（0.1745 vs 门 0.1728）——**上线后处置链（#15）的人工接受率 KPI 是质量运营的主反馈面**，误检水平由人工处置直接度量。
- **中性**：单评测集（Vul4J 30 案）/ 单模型（deepseek-v4-flash）/ 单判级链限定维持——换集/换模型须重跑质量门证据（后者另受迁移门约束）。
