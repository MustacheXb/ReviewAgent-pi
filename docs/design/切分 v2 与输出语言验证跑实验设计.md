## 1. 共同判定方法

### 1.1 对称 max σ 带（ADR-0007，#30 方法）

- 带宽 = 基线侧均值 ± **max(σ_base, σ_cand)**（两侧样本标准差较大者，方向无关；不取合并 σ 以免放大自由度）。
- 候选侧均值落在带内 = 差异在噪声底内（IN）；带外 = 真实差异（OUT）。
- 最小样本护栏：任一侧 n < 3 → `INSUFFICIENT_SAMPLE`，不判定。
- 一侧不可估 σ（如 1-rep）时带宽取可估侧 σ，报告如实标注（§3.3 zh 侧即此情形）。
- 工具：`runAlignmentGate`（src/metrics/alignment-gate.ts，#30 已落地）——两侧 `GateUnitSample` 输入即可复用。

### 1.2 计数型守卫判据不进 σ 带

不重 / 不误并的期望值恒为零（零方差，σ 带无意义）：判定口径 = **逐案例计数 + 非零即逐例调查**（描述性统计），不做带判定。σ 带只用于连续指标（不丢率、判定链指标、成本指标）。

## 2. #59 切分 v2 验证跑

### 2.1 数据域与组合清单

**候选池约束（实测事实）**：`composeComposite` 硬校验同仓（repoPath 一致）+ 文件级不相交 + 逆补丁干净套用（spec #48 实现决策 14）。30 案恰好 30 个独立 clone（一仓一案），其中同上游 slug 的仅 4 组：

| 组 | slug | 案例（文件互不相交，已核实） | 案例部分规模 |
|---|---|---|---|
| struts | apache/struts | VUL4J-29 / 30 / 33 / 35（4 个不同文件） | 4 文件 / 56 行 |
| spring-sec | spring-projects/spring-security | VUL4J-72 / 73 / 74 | 3 文件 / 21 行 |
| cxf | apache/cxf | VUL4J-15 / 16 | 2 文件 / 15 行 |
| uaa | cloudfoundry/uaa | VUL4J-39 / 40 | 2 文件 / 16 行 |

**构造期两个前置步骤**（实验脚本层，构造器 #52 零改动）：

1. **repoPath 统一改写**：同 slug 案例的 clone 目录互异（各自 fix commit 快照），构造 `CompositeCandidate` 时非锚候选的 `repoPath` 与 `snapshot` 一律改写 / 取自锚 clone——干净套用校验（`applyUnifiedDiff` 在锚快照上）兜住内容匹配，套不上即弃（构造痕留 manifest）。合成 MR 的 repoPath = 锚 clone（预取走真实仓库）。
2. **fixCommitAt 取数**：manifest 无 commit 时间、clone 无 .git → 构造脚本用 `gh api repos/<slug>/commits/<sha> --jq .commit.committer.date` 查 11 案（一次性，结果落 manifest 供重放）。锚定规则 = fix commit 最新者（#52 既有语义）。

**弃案风险（如实预期）**：非锚案例文件在锚 fix commit 时刻若已被后续提交改动 → 上下文不匹配 → 弃案；组内仅剩 1 案则组不可构造（≥2 硬校验）→ 弃组。矩阵可能从 4 组缩水，缩水后如实记录；若 < 3 组再评估扩池（§5）。

**基线数据**：复用 `runs/phase2-dsh/runs/vul4j/<案>/B/rep-{1,2,3}.json`（30 案 × 3 rep，verifier off）。harness 阶段 2 按 caseId + configId + model 三元组匹配——臂侧必须同 model（deepseek-v4-flash）。

### 2.2 规模档位与臂矩阵

验证域边界：10 文件 / 2000 行（`planShards` 同款配置）。四组按超界形态分维覆盖（单维 / 双维 / 边界邻域）：

| 组 | 处理臂档位（超界形态） | 预计片数 | 控制臂档位（域内） |
|---|---|---|---|
| struts | 24 文件 / 2400 行（双维超界） | 3（文件维 ⌈24/10⌉） | 9 文件 / 1500 行 |
| spring-sec | 24 文件 / 1800 行（单维：文件） | 3 | 9 文件 / 1500 行 |
| cxf | 9 文件 / 2400 行（单维：行） | 2（⌈2400/2000⌉） | 9 文件 / 1500 行 |
| uaa | 11 文件 / 2100 行（边界邻域微超界） | 2 | 9 文件 / 1500 行 |

- 案例部分很小（2–4 文件 / 15–56 行），规模主要由良性填充撑到档位（`generateBenignFill`，确定性：种子 = compositeId，FNV-1a → mulberry32；四类机械编辑，锚快照内与案例文件不相交）。
- 臂不变式由 `composeShardingArms` 预检（处理臂必超界、控制臂必域内，档位配错启动即拒——#57 既有护栏）。
- 控制臂统一 9 文件 / 1500 行（留边界余量防填充实际产出略超目标），跨组可比。
- 预计片数为估算，实际以 `planShards` 产出为准（报告记录 `shards.entries`）。

### 2.3 三判据（#57 harness 现状，零改动）

- **不丢**（`evaluateNoLoss`）：双臂各算；基线 = 逐案例 × rep 全部 findings 的去向轨迹（strict / loose 分列，`matchWindow` 缺省 = 合并层同款窗口）。
- **不重**（`evaluateNoDuplicate`）：只算处理臂；合并层不变量守卫，正确产物上恒空。
- **不误并**（`evaluateNoWrongMerge`）：只算处理臂；`mergeShardFindings` 同配置重放 + 判定链单筛映射真值，≥2 相异真值下标 = 误并。

### 2.4 判定协议（两组 σ 带对比）

主判指标：**strict 不丢率**（每臂每 rep 一个标量 = 该组基线 findings 的 strict 命中占比）；loose 口径并列报告不进主判。

- **对比 A（纯切分合并效应，spec 决策 15 核心）**：候选侧 = 处理臂逐组逐 rep strict 不丢率（4 组 × 3 rep = n 12）；基线侧 = 控制臂同指标（n 12）。带 = 控制臂均值 ± max(σ_t, σ_c)。带外 = 切分合并引入真实丢失。
- **对比 B（填充 + 组合效应）**：候选侧 = 控制臂（n 12）；基线侧 = **直跑自漂移底**——每基线案例的 LOO 命中率（rep r 的 findings 在其余 rep 结果中的 strict 命中占比，30 案例 × 3 rep 配对，纯脚本零 LLM 成本，与不丢同定义「X 的 findings 是否仍在 Y」）。带外 = 填充 + 组合引入超出直跑自然漂移的丢失。
- 归因链：控制臂带外（对比 B）而处理臂相对控制臂带内（对比 A）→ 填充效应主导；对比 A 带外 → 切分合并效应实锤。
- 不重 / 不误并：计数守卫（§1.2），非零即逐例调查并写报告。

**锚点键校准分析（AC5 素材，零 LLM 成本）**：对处理臂各片的 findings 以窗口 ±1 / ±3 / ±5 重放 `mergeShardFindings`，对比合并数与误并计数 → 锚点键 ±3 起步值的校准建议（只改配置不改架构，spec #48 Further Notes 预留点）。

### 2.5 执行编排与断点粒度

- 执行通道：DSH 内核（en，deepseek-v4-flash，与 phase2-dsh 基线同通道同 model）——`DshKernelDriver.runUnit` 形状适配 `ExperimentUnitExecutor`（#57 runner-adapter 注入点），与生产 CLI 走同一编排函数 `orchestrateReview`（spec #48 用户故事 18）。
- **断点粒度 = 组**：验证 harness 无断点续跑（组粒度重跑即重烧，#57 留痕议题）——处置为**逐组独立调用** `runShardingValidation`（groups 传单元素数组）+ 逐组落盘 `report.json`（`<reportDir>/<groupId>/`）。接口零改动；单组失败 / 中断只重烧该组。
- 失败隔离沿用四阶段（arms / baseline / treatment / control）：处理臂失败即弃组不烧控制臂（#57 既有）。
- rep 间串行（与生产语义一致，兑现跨片前缀缓存）。

### 2.6 执行矩阵汇总

4 组 × 2 臂 × 3 rep：处理臂每 rep 2–3 片 run + 控制臂每 rep 1 次直通 run ≈ **48 次 run**（片数以 pilot 实测为准）。

### 2.7 预算（净 LLM token，i+o+cacheRead 口径）

- 实测锚：Phase 2 B 单 run 均值 ≈49K token（30 案 × 3 rep，小 diff 中位 7 行）。
- 臂侧 run 为大 diff（700–2400 行）——input 随 diff 文本与预取规模上推，外推单 run ≈100–250K token（**未实测，pilot 校准**）。
- 全矩阵：48 run × 100–250K ≈ **4.8–12M**；弃案重试与裕量 +20% → **≈4–10M 口径**。
- **Pilot（预算确认机制）**：先跑 struts 组 × 1 rep × 双臂（≈3 片 + 1 直通 ≈ 4 run）——校准单 run 成本、片数、弃案情况，实测后修正全矩阵预算再放行。pilot 本身 ≈0.4–1M。

| VUL4J-42 | 4 | plexus-archiver | 高密度 findings + 最大案（3 文件 / 133 行） |

**执行**：5 案 × Config B × 1 rep，DSH 内核 `language: zh`，model deepseek-v4-flash，judgeModel **glm-5-3-260814（与 Phase 2 en 基线逐字节同口径，提示词零改动）**。

**人工检查项**（逐案）：

1. zh findings 语言质量：title / description / evidence 中文可读；代码摘录 / 路径 / 标识符 / 枚举未翻译（spec #49 决策 2）。
2. 语言门行为：audit 中 Zone A 消息为 zh 冻结序列；语言门放行 zh findings（含 CJK）。
3. **judge 匹配行为（核心）**：中文 finding ↔ 真值的语义匹配无语言性错配（漏匹配 / 误匹配逐对人工复核）。
4. 判定链指标可计算：judge 产出形状与 en 一致，指标管道零改动跑通。

**异常处置**：任一案 judge 匹配异常 → **停全量**，回报；judge 侧任何改动须显式标注「破坏基线可比性」（spec #49 Out of Scope 冻结面），改不改由用户拍板。

### 3.2 全量跑（AC2）

- 30 案 × Config B × 1 rep，DSH 内核 zh，model deepseek-v4-flash（与 en 基线同 model / verifier off / judge 同口径——差异只剩输出语言单变量，spec #49 用户故事 13）。
- 走既有实验 runner（`plan.outputLanguage: "zh"`，#58 已贯通；manifest 落 `outputLanguage` 字段，断点续跑按语言口径隔离）。
- 数据落盘：`runs/<experimentId>/`（新 id，不复用 phase2-dsh 目录——口径维度隔离，runner 既有护栏）。

### 3.3 zh vs en 对比（AC3）

- 两侧：基线侧 = phase2-dsh **B 配置 en** 3-rep（n = 90）；候选侧 = zh 1-rep（n = 30）。
- 指标面：判定链指标（lineRecall / linePrecision）+ 成本指标（totalTokens / cacheHitRate）+ findings 数——即 `DEFAULT_GATE_METRICS` 同款口径，`runAlignmentGate` 现成工具。
- σ 处理：zh 侧 1-rep 单点无 σ → 带宽取 en 侧 σ（单侧退化，ADR-0007 语义内，报告如实标注）；若结果带外，追加 zh 侧 2 个 rep 补 σ（追加预算另批）。
- **按语言分口径**：指标、报告、manifest 全程 zh / en 分列，不跨语言混比（spec #49 用户故事 14）；configId 过滤只比 B。

### 3.4 预算（净 LLM token）

- sanity 5 案 ≈ 5 × 49K ≈ **0.25M**。
- 全量 30 案 × 1 rep：en 实测口径 ≈1.48M；zh 输出长度不确定（分词效率差异）±30% → **1.0–2.0M**。
- 判定链 judge（GLM-5.3 语义匹配，30 案）≈ **0.1–0.3M**。
- 合计 ≈**1.3–2.5M**。

## 5. 风险与限制

| 风险 | 处置 |
|---|---|
| 组合干净套用弃案 → 组缩水（<4 组） | 构造痕如实留 manifest；缩水后 n 仍 ≥3 则判定有效；<3 组评估扩池（pool 内另有 6 组同 slug 未物化案例，扩池需 clone 物化 + 预算另批） |
| 臂侧 run 成本外推失准 | pilot 单组先行校准，预算在批准点以实测修正 |
| 验证 harness 无断点续跑 | 逐组独立调用 + 逐组落盘（§2.5），断点粒度 = 组 |
| zh 判定链质量异常 | sanity 即停协议（§3.1），改动与否由用户拍板（冻结面标注纪律） |
| zh 1-rep 无 σ | 带宽取 en 侧 σ；带外追加 rep 另批（§3.3） |
| 合成组合非真实超界 MR（填充是机械编辑） | spec #48 决策 14 既有边界：结论限定「合成数据域内」；真实超界 MR 回流是上线后数据资产（Out of Scope） |
| model 线上漂移（deepseek-v4-flash 下线等） | 与 Phase 2 基线同 model 是 harness 匹配硬约束；若退役，全实验（含基线重跑）重议 |
