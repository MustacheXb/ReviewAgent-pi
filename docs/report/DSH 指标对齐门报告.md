# DSH 指标对齐门报告（#29）

> **范围**：票 #29（Ticket 12: 指标对齐门）——DSH 内核在 gateway 口径 45 单元子集上真实重跑，与冻结薄 harness（POC1）既有结果做四指标 ±1 std 对照
> **交付形态**：本报告 + `runs/dsh-vul4j-gateway/`（45/45 单元产物）+ `runs/dsh-gateway-smoke-r3/`（冒烟）+ ADR-0006 实现注记；门不过 → 触发诊断票 #30
> **报告日期**：2026-09-11

## 1. 概述与一句话结论

本报告回答迁移验收第二层门的问题：**DSH 内核替换冻结薄 harness 后，实验主数据是否可接管**（Recall / Precision / Token / CacheHit 落在 POC1 ±1 std 波动带即认定运行时互换无系统偏差）。

一句话结论：**门不过（按票面字面：池化口径 18/20 格落带、2 格出带）——但归因清单显示偏差主体在运行时不可控面**：两侧首个请求逐字节一致、一切分歧始于模型自身响应；POC1 **自身**同单元重跑呈现完全相同的分歧模式且摆幅更大（findings 0↔3、输出 token 5.9×、rounds 1↔5），自门检验 28 次完整尝试中 11/28 的 totalTokens 落在 POC1 自己的带外。**带宽窄于协议固有 run-to-run 方差**——2/20 OUT 不构成 DSH 运行时偏差的证据；门的检验力问题立诊断票 #30（POC1-vs-POC1 校准跑，需预算批准）。

## 2. 对照设计

| 维度 | 内容 |
|---|---|
| 单元矩阵 | Vul4J 3 case（VUL4J-38 / 52 / 79）× 配置 A–E × 3 reps = **45 单元**，与 POC1 完全同构 |
| 判定链 | verifier **off** / judge **false** / 规则口径 verdicts / anchor = C / humanReviewRate 0.1（seed `poc1-human-review-2026`）——与 POC1 逐项一致 |
| 模型 | `deepseek-v4-flash` @ 火山引擎网关（OpenAI 兼容；ADR-0002 锁定档 thinking + effort high） |
| 运行时（基线） | POC1 冻结薄 harness（零 DSH 依赖；`30d7e16` 时点构建） |
| 运行时（对照） | **review-dsh 内核**（kernel-host 长驻进程，经 #27 实验 runner 路径驱动） |
| 指标计算 | metrics 管线同径：`evaluateRun` 逐单元 → `flattenRunMetrics` → 池化；四指标 lineRecall / linePrecision / totalTokens / cacheHitRate |
| 判定带 | POC1 per-config **mean ± 1 × 样本 std**（`summarizeDefined`，n−1 分母）；DSH per-config mean 落带 = IN |

**口径说明**：主口径为池化 per-config（每配置全部 9 单元为独立样本，σ 为真实单元样本 std）。另报两种分层口径作稳健性参照：POC1 报告主口径（rep2+ 热层，case-mean n=3）与冷热 40 格合并——热层 σ 被 case-mean 预平均压小、带更窄。三口径数字均列 §3；门结论在三种口径下一致（不过），出带格数随口径细化而增加（机制见 §4.4）。

**对账校验**：本报告的池化计算与 POC1 REPORT.md §7 的 45 单元实际总账**逐 token 一致**（11,287,939），证明对照计算与基线报告同径。

## 4. 判定结论与偏差归因

### 4.1 结论：门不过

按票面协议「四指标落在 ±1 std 波动带即认定运行时互换无系统偏差」：**门不过**（主口径 2/20 出带）。按票面要求产出以下归因清单，并触发诊断票 **#30**。

### 4.2 归因一：运行时请求构造忠实（逐字节证据）

POC1 ↔ DSH 同单元（VUL4J-38/D/rep-1）审计逐请求对照（`model + effort + messages + tools` 序列化字节）：

- **request 1 完全一致**（8,280 字节）——两侧喂给网关的首个请求逐字节相同，prompt 构造、工具 wire、模型参数无运行时差异
- **首个分歧出现在 request 2 的 assistant 消息**（消息序 3）：POC1 侧为文本摘要，DSH 侧为空 content + `review.get_diff`/`review.get_file` 工具调用——分歧由**模型响应**引入，非请求构造
- 工具调用分布完全同构：DSH 45 单元 `{0 调用: 18（A/B 全部）, 6 调用: 27（C/D/E 全部）}`，与 POC1 逐配置一致（C 182 / D 223 / E 257 总调用 ≈ 每单元 6）——内核工具层忠实

### 4.3 归因二：rounds 混合比位移驱动 token/cache 偏移

终局 45 单元的检视轮数分布（六阶段循环自主决定结束时机，硬上界 5）：

| rounds | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| POC1 | 24 | 4 | 6 | 1 | 10 |
| DSH | 35 | 4 | 2 | 2 | 2 |

多轮单元（rounds ≥ 3）从 **17 个降到 6 个**。机制：轮数越少 → 重复注入上下文的请求越少 → 长前缀复用次数越少 → cacheHitRate 降、totalTokens 降。这与全部出带格的方向一致（C cacheHitRate 降；C/D/E token 降；B 单轮配置 token 反升），且与 POC1↔DSH 间隔 3 天的网关部署/模型行为漂移预期一致——**轮数是模型响应侧变量，不在 DSH 运行时的控制面内**（其协议固有性的直接证据见 4.4）。

### 4.4 归因三：POC1 自身重跑声底（决定性反事实）

POC1 当日执行在 38 个单元上留下了**两次尝试的审计**（同 harness 构建、同日、同配置、同 rep——多段执行/重跑所致）。逐对请求字节对照：

- **38/38 对：request 1 逐字节一致，首个分歧全部始于 assistant 消息**——与 POC1↔DSH 的分歧模式完全相同，证明该模式是协议固有而非 DSH 特有
- **14 对结构匹配**（两侧 rounds 相同、均未截断、请求数差 ≤1，即两次都是完整尝试），量化摆幅：

| 单元 | rounds | findings | 输出 token（尝试1/尝试2） | 倍率 |
|---|---|---|---|---|
| VUL4J-52/A/rep1 | 1↔1 | **0↔3** | 4,376 / 24,590 | 5.6× |
| VUL4J-52/A/rep2 | 1↔1 | **2↔0** | 16,694 / 2,964 | 5.6× |
| VUL4J-79/B/rep1 | 1↔1 | **1↔4** | 5,200 / 8,553 | 1.6× |
| VUL4J-52/B/rep2 | 1↔1 | 1↔0 | 21,285 / 3,629 | 5.9× |
| （其余 10 对同量级：输出 1.1–3.4×，findings ±1~3） | | | | |

- 另 24 对含中断尝试，rounds 摆幅最高 **1↔5**（VUL4J-38/D/rep2、VUL4J-38/E/rep1 等）——同单元同 harness 的轮数本身不是稳定量

**自门检验**：把 POC1 自己的 28 次完整尝试（14 对 × 2）逐个过 POC1 自身的 ±1σ 池化带——**totalTokens 11/28 出带、cacheHitRate 9/28 出带**（lineRecall 5/28、linePrecision 4/21）。

含义：若把 POC1 原样重跑一遍按同门判定，按此声底预期同样出带。**门的带宽窄于协议固有 run-to-run 方差，2/20 OUT 不构成 DSH 运行时偏差的证据**。正式的噪声底校准跑立诊断票 **#30**（需预算批准，本报告未执行）。

> cacheRead 的对内摆幅（最高 4.5×）不单独归因于模型侧——它是响应长度差与网关缓存时序（异步预热/TTL）的混合效应；本归因链只依赖干净的模型侧证据（findings、rounds、输出 token、请求字节）。

### 4.5 归因四：C/linePrecision 基线统计无效

POC1 的 C 配置 9 单元中仅 2 个产出 findings（precision 有定义），±1σ 带由 2 个样本构成（0.3750±0.1768）——该格判定无统计意义。DSH 侧 C 有 8 个单元产出 findings（n=8，0.1750），两侧 n 的悬差本身就是 rounds/响应漂移（§4.3）的表现。

### 4.6 归因五：turn 超时单点失败（与指标偏差分开归因）

DSH 首跑中 VUL4J-38/D/rep-3 失败一次：`review-runtime: turn 5 did not end within 900000ms`——网关停滞（单请求 600s 超时 + 适配器重试整周期 > 900s turn 预算）。该预算是 **#29 新增护栏**（`REAL_LLM_TURN_TIMEOUT_MS`，POC1 无此护栏，属严格更优），作用是给挂死单元止损而非改变检视行为。resume 重跑同单元通过（rounds=1 / findings=2，281s），计入 DSH 统计。**该失败与四指标偏差无关**；POC1 首跑当日同样经历多段执行（38 单元双审计即其产物）。

### 4.7 方向性核对

- token：双向（B +8%，A −18%，C −19%，D −50%，E −7%）
- lineRecall：双向（B/C/E 升，A/D 降）
- cacheHitRate：C/E 降，A/D 与基线持平（Δ ≤ 0.0006）

无任何指标呈现系统性单向偏移——与「运行时互换引入稳定偏差」的特征不符；与「模型响应非确定性 + rounds 混合比漂移」的随机方向特征一致。

*结论一句话：**门不过但归因干净**——DSH 内核请求构造逐字节忠实、工具层同构、无系统性方向偏差；出带格由协议固有的模型响应非确定性（POC1 自身重跑可复现同模式且摆幅更大）与 rounds 混合比漂移驱动，位于运行时不可控面。DSH 内核接管实验主数据的工程判断建议以 #30 校准跑的噪声底为最终依据。*

> **#30 已收口（2026-09-12）**：噪声底实测——POC1 自身重跑过同一 ±1σ 门出 1 OUT（正向）/ 3 OUT（反向，方向依赖）；DSH 的 2 OUT 在噪声底量级内、OUT 格不重叠、单元配对偏差四指标全部更小；对称 max σ 修订口径下 DSH 除基线 n=2 统计无效格全落带。**本报告的「门不过」判定据此定性为门的检验力问题，非 DSH 运行时偏差。** 完整数据见《[DSH 指标对齐门噪声底报告](./DSH%20指标对齐门噪声底报告.md)》。
