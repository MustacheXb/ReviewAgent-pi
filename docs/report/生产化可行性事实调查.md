## 1. 项目定位与架构形态

### 1.1 定位

- **一句话定位**：「基于 DeepSeek Harness 的低 Token、高质量代码检视 Agent：用最小充分上下文与缓存稳定循环，以 20~30% 的 Token 成本获得接近全量上下文的检视质量。**终点是落地到企业内部代码托管平台的 MR 检视**。」（`README.md` L3 / `CONTEXT.md` L3）
- **双重身份**：同时是 AI4SE 研究项目——以 VUL4J 单缺陷 MR 为基准、五配置（A–E）受控实验、四层判定链，论文主数据在 `docs/report/`（`README.md` L5）。
- **术语权威**：`CONTEXT.md`（领域词汇表，含核内/核外运行时边界、Zone A/B/C、RIE/CARC 等）。

### 1.2 形态：pnpm monorepo + 双运行时 + 双 CLI

- **核心结论**（报告 §1/§5）：

  - **锚塌缩 caveat**：S 级语义是「显著超越一个塌缩的 C 锚」（C 热 recall 仅 0.0097），论文引用须连同注记（§3.3）。

## 3. 生产化差距（重点）

来源：《docs/design/Config B 生产化方案——差距分析、推荐路线与修改建议.md》（未跟踪新文件，读工作区版本；221 行）。

### 3.1 决策内容（2026-09-17 拍板，文档文首说明）

- **生产检视形态 = Config B**：零工具 + Zone B 与固定管线确定性预取（Diff → Symbol → Reference → Call Chain），无 ledger、无全仓注入、无自主检索；运行形态 `{ toolsEnabled: false, prefetch: true, fullRepo: false, stablePrefix: false, ledger: false }`。
- **不设风险升级门**：高风险 MR 同样走 B 平推；升级门保留为后续可选杠杆。
- 一句话结论（原文）：「B 是数据站得住的生产形态（三侧 S 级、precision/F1 双冠、成本有界、FP 天然安全）；**上线前必须补四件事**——MR 边界护栏、输出语言决策、模型迁移门（若换模型）、质量回流日志；骨架裁剪与风险自适应预取等第一批生产数据后再动。」

### 3.2 数据依据（文档 §1.3，Phase 2 主数据 judge 口径 main 侧 90 单元均值）

| 指标 | B 实测 | 判读 |
|---|---|---|
| linePrecision | 0.7835 | 五配置最高 |
| lineF1 | 0.5763 | 稳定口径最高 |
| lineRecall | 0.4671 | 仅次于 A；为 C（0.1341）的 3.5 倍 |

### 3.4 骨架修改的协议决策：推荐保守路线（文档 §4）

- 分叉问题：裁阶段 4 等骨架改动会改变 Zone C 字节——生产形态与实验冻结形态分叉，生产指标不再与 A–E 数据直接可比；六阶段骨架是 ADR-0006 定义的内核形态。
- **推荐保守路线**：生产先原样上冻结形态（6 阶段全跑）→ 跑完第一批真实 MR → 再裁阶段 4 + 标定风险自适应阈值 → 裁剪后做一次对齐验证（修改形态 × B × 30 案 × 3 rep 与冻结 B 在对称 max σ 带内对比，#30 方法）。
- 激进路线（现在就裁）被评估为损失首批生产数据与冻结形态的可比性。

### 3.5 已有方案 vs 悬而未决的汇总

- **已有明确方案**：上述 8 项差距全部有修改方案、实现锚点对照（文档附录表）与验收口径建议；模型可换的工具链（smoke/画像/parity）已落地（#43–#47）。
